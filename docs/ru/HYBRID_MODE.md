# Задачи AI и совместный режим

[English](../en/HYBRID_MODE.md) · [Настройка провайдеров](AI_MODES.md)

1. Откройте Git-проект хотя бы с одним коммитом и выберите **Задачи AI**. Выберите GPT, Gemini, исполнителя с ревью другой модели, двойное ревью или распределение по типу задачи. В двойном ревью две модели независимо разбирают один diff. При автоматическом распределении Gemini предпочтителен для интерфейса, GPT для архитектуры и реализации. Можно указать предпочтительного исполнителя. Если выбранная модель недоступна или свежий официальный отчёт показывает исчерпанную квоту, проверьте обновлённый план перед запуском.
2. Опишите задачу и укажите до 16 относительных путей к UTF-8 файлам, по одному на строку. Исполнитель получит версии выбранных файлов из коммита. Включите **Разрешить создание и удаление файлов по указанным путям**, чтобы добавить новые пути или разрешить предложить удаление. Исключите конфиденциальные файлы и данные из запроса.
3. Выберите, запускать ли тесты проекта. Нажмите **Подготовить задачу**, проверьте модели и пути, затем **Подтвердить и запустить**. Исполнитель планирует и предлагает правки. momp собирает diff во временном Git-репозитории и запускает `git diff --check`. Ревьюеры получают сводку, diff и результаты запрошенных тестов.
4. Прочитайте ревью. Нажмите **Применить патч…** и **Подтвердить применение**, чтобы изменить рабочие файлы. Патч также можно скачать. Перед применением momp сверяет исходный коммит, индекс и содержимое затронутых файлов. Если вы запросили тесты, они должны пройти. **Откатить патч…** отменяет патч, если затронутые файлы совпадают с результатом применения. Посторонние правки и файлы в индексе сохраняются.

Завершённые этапы остаются в истории. **Приостановить** останавливает активные этапы, а **Повторить незавершённые этапы** использует те же модели. На каждый этап модели отводятся три попытки. Если ревьюер недоступен, можно подождать, повторить попытку или завершить задачу без этого ревью. Если недоступен исполнитель, подготовьте отдельную задачу с другой моделью и подтвердите её.

## Запуск тестов в изоляции

Установите локальный Docker с поддержкой Linux-контейнеров. Загрузите доверенный образ Bun и задайте `MOMP_TEST_RUNNER_IMAGE` перед запуском momp. Для релизных тестов используется `oven/bun:1.4.4`.

```sh
docker pull oven/bun:1.4.4
export MOMP_TEST_RUNNER_IMAGE=oven/bun:1.4.4
```

В PowerShell выполните `$env:MOMP_TEST_RUNNER_IMAGE = 'oven/bun:1.4.4'`. Команда `bun test` запускается на снимке коммита с патчем, без сети, с корнем контейнера только для чтения и без подключения исходной рабочей копии. Образ должен содержать `/bin/sh`, `tar` и Bun. Используйте автономные тесты или образ с заранее подготовленными зависимостями. Для крупных снимков и Git-подмодулей запустите проверки отдельно. Ревьюеры получают команду, статус и числа тестов, если они доступны. Сырой вывод тестов моделям не передаётся.
