# Полное ревью momp — 24 октября 2026

## Область проверки

Ревью выполнено по всему собственному коду проекта, а не только по diff обновления: API, RPC и жизненный цикл сессий, модели/роли, хранение данных, авторизация, совместимые skills, React-компоненты и hooks, CSS, CLI, установщики, desktop Rust, updater и release workflow. Тесты прочитаны вместе с реализацией. Работа разделена между четырьмя ревьюерами; изменения на границах модулей сверены отдельно.

Точный перечень файлов и глубина проверки: [покрытие ревью](code-audit-coverage-2026-10-24.md).

Ограничения покрытия: словари переводов проверены по полной AST на структуру, ключи и интерполяции, но не сертифицированы лингвистически. SVG проверены как XML на активное содержимое; бинарные изображения — по формату. Геометрия иконок и каждый inline style не являются построчным визуальным аудитом. Сторонний `node_modules`, сгенерированные bundles, машинные lockfiles и бинарные EXE не выдаются за вручную прочитанный исходный код: для зависимостей используются advisory-сканирование и интеграционные проверки, для EXE — отдельный release smoke.

GitNexus не нашёл пригодного индекса. Использован локальный Graphify с последующей сверкой реальных импортов/вызовов. Синтетические воспроизведения выполнялись в временных каталогах и с тестовыми транспортами, без изменения пользовательских файлов и без запросов к платным моделям.

## Остальные исправления

- **RPC:** завершение сессии больше не ждёт диалог, который отменялся только после завершения; поздний custom UI освобождается, а не монтируется на уничтоженную сессию.
- **Роли GPT/Gemini:** используется SDK `applyRoleModel`, включая thinking suffix; выбор роли до первого сообщения сохраняет роль и не перезаписывает глобальный default. Прямой выбор модели по-прежнему сохраняет явное предпочтение.
- **Hooks:** успешная загрузка transcript возвращает явный результат для promotion `/name`, `/compact`, `/handoff`; поздняя загрузка после unmount не открывает новый SSE. Учитывается thinking `off`.
- **Уведомления:** `ask` и `plan_review` считаются запросами внимания; для `ask` не читается отсутствующее поле `title`.
- **Файлы:** конфликт загрузки из проекта A не превращается в подтверждение перезаписи в B; уже отправленная загрузка сохраняет исходное назначение.
- **Черновики файлов:** дополнительно воспроизведена потеря несохранённого текста при обычном A→B→A между открытыми файлами. Черновики теперь принадлежат AppShell и переживают remount редактора. Проверены сохранение во время переключения, более поздняя правка, watcher до ответа PUT и потерянное подтверждение уже выполненной записи. Блокировка сохранения действует в пределах identity файла/контекста.
- **Настройки:** можно сохранить удаление последнего MCP-сервера; переименование провайдера не перезаписывает существующего; импорт локальной модели сохраняет `models.yaml/json` и отказывается затирать повреждённую конфигурацию.
- **Windows/Git:** сравнение путей учитывает разделители и регистр; корневой checkout и linked worktree определяются корректно.
- **Skills:** install/update metadata распознаёт совместимые `.agents`, `.agent`, Codex-каталоги; YAML toggle корректно обрабатывает конфликтующие старые флаги.
- **Интерфейс:** Escape в диалоге не останавливает агента; основные generic settings получают доступные имена; исправлен контраст accent-кнопок и mobile textarea 16px.
- **Сборка:** Intel Mac получает x64 native packages; кэш Bun проверяет версию, target, размер и hash; отсутствие/пустота EXE или payload приводит к ошибке, а не успешному завершению сборки.
- **Desktop startup:** параллельные экземпляры больше не удаляют общий staging; распаковка защищена межпроцессным lock, проверяет готовность payload и использует уникальный staging. Повреждённый прежний runtime сохраняется отдельно. Автоматическое удаление других версий отключено, чтобы не удалить работающий экземпляр. Старые и аварийные каталоги теперь занимают место до явной очистки.
- **Авторизация:** страница HTTP Basic показывает реальный логин `omp`, а не неверный `momp`.

## Зависимости

Сборка и runtime проекта используют Bun. Оба lockfile удовлетворяют manifest/overrides, но отдельные разрешённые caret-версиями пакеты в npm и Bun отличаются; одинаковый полный dependency tree не заявляется. Релиз воспроизводится именно по `bun.lock` с `--frozen-lockfile`.

Проверены оба lockfile. Не использовался `npm audit fix --force`: предложенный сканером откат OMP до старого major не совместим с задачей. Применены обновления в текущих семействах и явные overrides там, где upstream фиксирует старую транзитивную версию. Для KaTeX 0.18.2 отдельно проверяется реальный production Markdown pipeline: inline/display math, GFM, Mermaid source и блокирование исполняемого HTML/небезопасных math links.

Первичный npm production audit показывал 13 проблем, включая одну critical. Это не весь browser bundle: frontend-библиотеки в проекте находятся в devDependencies, поэтому дополнительно выполнены **полный** npm audit и Bun audit. После исправлений оба сканера не сообщили известных advisories на момент проверки. Это не доказательство отсутствия ещё неизвестных уязвимостей.

Источники: [Next.js Windows RCE](https://github.com/advisories/GHSA-p293-qw3h-jr36), [Next.js 16.4.3](https://github.com/vercel/next.js/releases/tag/v16.4.3), [Zod](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5), [DOMPurify](https://github.com/advisories/GHSA-cg2g-xh64-v4q7), [KaTeX](https://github.com/advisories/GHSA-238p-pmpm-9mq7), [Puppeteer 25.16.0](https://github.com/puppeteer/puppeteer/releases/tag/puppeteer-core-v25.16.0).

## Открытые замечания и границы

1. **P2 — клавиатурная доступность составных списков.** Строки сессий, файлов, вкладок, моделей и skills местами остаются mouse-only; hover-only действия не раскрываются с клавиатуры. Затронуты `SessionSidebar`, `TabBar`, `FileExplorer`, `BranchNavigator`, `ModelsConfig`, `SkillsConfig`. Нужна отдельная согласованная реализация selection/action controls с браузерной проверкой, а не механическое добавление `tabIndex` и опасных Delete-shortcuts.
2. **Несохранённый draft при явном закрытии файла.** Обычное переключение файлов и watcher/save races исправлены, но явное закрытие вкладки, сброс workspace и перезагрузка приложения очищают in-memory draft. Подтверждение закрытия и постоянное хранение пока не реализованы. Сохранения одного физического пути через разные context identity не сериализуются общей файловой блокировкой.
3. **Произвольные расширения.** Отмена UI устраняет воспроизведённый deadlock. Расширение с произвольной бесконечной работой всё ещё может задержать shutdown; универсальный forced timeout не вводился.
4. **Ресурсы и долгие сессии.** Не выполнен многосуточный soak-test. Retention старых AuthStorage после invalidation требует отдельного измерения; подтверждённой утечкой это не объявляется.
5. **Реальные аккаунты.** Unit/integration tests ролей используют SDK resolver и изолированные настройки, а не успешные ответы GPT и Gemini. Отозванный токен ChatGPT и региональное ограничение Google не исправляются обновлением приложения.
6. **Платформы.** Нет физической проверки iOS и macOS. На локальной Windows-машине отсутствует MSVC linker; 10 native-тестов уже прошли в Windows CI. Smoke конкретного EXE выполняется в чистом CI: подмена HOME/LOCALAPPDATA не изолирует все Windows Known Folders, поэтому native launcher не запускается как якобы полностью изолированный профиль обычного пользователя.
7. **Удаление каталогов.** Рекурсивное удаление файлов не транзакционно на уровне ОС; исправление порядка не исключает частичного удаления проекта при ошибке диска/прав.
8. **Подпись.** Portable EXE не имеет Authenticode-подписи; hash сверяет целостность относительно GitHub, не идентичность подписанного издателя.

## Проверки и релизный барьер

Для подтверждённых исправлений добавлены регрессии с воспроизведением исходного поведения. Локальные точечные проверки не заменяют полный прогон после объединения. Перед релизом обязательны свежие Bun tests, TypeScript, адресный lint, тесты PowerShell/Bash установщиков, Windows cargo tests, production build и smoke именно собранного EXE в чистом профиле.

Свежий локальный прогон после исправления переключения файлов (без копии тестов в generated desktop staging): **648 passed, 5 skipped, 0 failed**, 653 теста / 122 файла. Пропуски относятся к Windows symlink/Unix permissions и Node-only proxy проверке; они не считаются пройденными. TypeScript прошёл без ошибок. Синтетические установщики PowerShell 5/Bash и helper обновления прошли проверки отказа, hash, rollback и путей с пробелами/кавычками.

[CI #44](https://github.com/domovoyproj/momp/actions/runs/40031073976) до последнего draft-fix выполнил 634 Bun tests (2 skipped, 0 failed) на Linux и Windows, 10 Rust tests и оба PowerShell installer/helper tests. Workflow был намеренно отменён на staging, чтобы не выпускать прежний кандидат без дополнительного исправления. Успешные тесты отменённого запуска не выдаются за успешную сборку нового EXE.

Production web artifact из CI #43 проверен в Chrome: реальный Mermaid SVG, Mermaid math labels и KaTeX, светлая/тёмная темы, сохранение одноразового файла после watcher-изменения, мобильная ширина 390×844 без горизонтального переполнения. В этих сценариях browser console не показала warnings/errors. На этом же артефакте воспроизведена потеря draft при переключении; для нового исправления добавлены 17 регрессий. Это синтетические transcripts без запросов к GPT/Gemini.

Полный ESLint завершился с **0 errors, 2 warnings**: неиспользуемый import в `app/api/sessions/[id]/route.ts` и параметр в `app/global-error.tsx`. Generated staging исключён из анализа; правила memoization не отключались — семь диагностик устранены корректными границами memo/dependencies. CommonJS launcher/config исключены только из запрета `require`, поскольку это их штатный формат.

Ручной workflow создаёт только **черновик** релиза после успешных jobs. Публикация допустима после проверки артефакта и интерфейса; сам факт этого отчёта или зелёных unit tests не означает, что EXE уже опубликован или успешно отвечают обе модели.
